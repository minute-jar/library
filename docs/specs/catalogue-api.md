# Catalogue API

The JSON API through which the website browses and searches the public library (ADR-0003). Unlike the interface with family servers (`interface-v1.md`), nothing here is signed: it is the service's own API, read by its website, and it may change with it. It is anonymous and read-only, and every caller receives the same answer for the same request.

## Browsing and searching

`GET /api/catalogue` answers the shared items at their latest version, newest first, twenty to a page:

```json
{
  "items": [
    {
      "item": "<32 hex>",
      "version": 2,
      "type": "bank",
      "title": "Irregular verbs, part 1",
      "licence": "CC-BY-SA-4.0",
      "author": {"pseudonym": "Owl", "editorial": false},
      "derived_from": null,
      "metadata": {
        "language": "en-GB",
        "subject": "english",
        "ages": {"min": 9, "max": 11},
        "description": "The fifty most common irregular verbs.",
        "curriculum": {"country": "GB", "year": "Year 5", "topic": "Verb forms"}
      },
      "selection": false,
      "signals": {"families": 0, "ratings": [0, 0, 0, 0, 0]},
      "published_at": "2026-11-20T18:00:00Z"
    }
  ],
  "total": 1,
  "page": 1,
  "pages": 1
}
```

Each entry has the fields of an index entry (`interface-v1.md`, Index), its signals counted when asked; a withdrawn item or one hidden from new imports (`interface-v1.md`, Reports) is left out, and a withdrawn version gives way to the latest one before it, as in the index. Every parameter is optional; together they narrow the catalogue to the items that match all of them. Values are compared without regard to case.

| Parameter | Keeps the items |
|---|---|
| `language` | in that language: a BCP 47 tag, where `fr` also matches `fr-FR` and `fr-CA` |
| `subject` | of that subject |
| `age` | meant for that age, from 0 to 255: `ages.min <= age <= ages.max` |
| `country`, `year`, `topic` | whose curriculum has that country, school year or topic |
| `selection` | `true`: marked Selection by the operator's team, or shared by the editorial account (`moderation-api.md`, Selection); any other value is malformed |
| `q` | whose title, description, subject or curriculum topic hold the words searched, in any inflected form, English or French (web search syntax: `"exact phrase"`, `or`, `-excluded`) |
| `page` | the page asked for, from 1; a page past the last answers no items |

A malformed `age`, `language`, `selection` or `page` answers `400` with `{"error": "bad_filter"}`.

## Filters

`GET /api/catalogue/filters` answers the values the catalogue's items take, sorted, for the website to offer as filters:

```json
{
  "languages": ["en-GB", "fr-FR"],
  "subjects": ["english", "mathematics"],
  "curricula": [{"country": "GB", "year": "Year 5", "topic": "Verb forms"}]
}
```

## Item page

`GET /api/items/{item}` answers what the website's item page shows of a shared item:

```json
{
  "item": "<32 hex>",
  "version": 2,
  "...": "every field of a catalogue entry, at this version",
  "content": {"...": "the bank or learning path, as signed"},
  "media": [{"digest": "<64 hex>", "type": "image/png", "size": 70}],
  "editorial": null,
  "versions": [
    {"version": 2, "published_at": "2026-11-22T10:00:00Z"},
    {"version": 1, "published_at": "2026-11-20T18:00:00Z"}
  ],
  "comments": [
    {"comment": "<32 hex>", "pseudonym": "Lark", "text": "Learnt in a week.",
     "published_at": "2026-11-27T10:00:00Z"}
  ],
  "profile": "Owl"
}
```

- The entry is the item's catalogue entry: its latest version that is not withdrawn, signals counted when asked. An item hidden from new imports (see Reports in `interface-v1.md`) has no page.
- `content` and `media` are those of the signed shared item at that version (`interface-v1.md`, Shared items).
- `versions` lists every version that is not withdrawn, newest first; each can be downloaded as an item file (`interface-v1.md`, Item files) at `GET /api/items/{item}/versions/{version}/file`.
- Its ratings and published short reviews are at `GET /api/items/{item}/ratings` (`interface-v1.md`, Ratings, For the website).
- `comments` lists the item's published comments, oldest first (see Comments below): never one held, refused, removed, or hidden by a report waiting for a moderator.
- `editorial` is `null`, unless the editorial account shared that version (`author.editorial` true, ADR-0002): then it says whether the version was generated by AI and who read it before it was shared, as the share said (`interface-v1.md`, Shares, Editorial account): `{"ai_generated": true, "read": {"by": "moderator", "handle": "Heron", "at": "2026-11-26T08:00:00Z"}}`, or `"read": {"by": "operator", "at": "..."}` when the operator read it. `handle` is the moderator's handle as the operator named them.
- `profile` is the pseudonym under which the author's profile is found now (see Author profiles below): the one their library account holds, which may differ from `author.pseudonym`, the one this version was published under. `null` for an item that no library account shared, and for a version published under an earlier pseudonym unless the author chose to show those on their profile (`show_earlier_pseudonyms`, `accounts-api.md`).
- An item withdrawn, hidden, never published or malformed answers `404` with `{"error": "unknown_item"}`.

## Author profiles

An author's profile shows their items and how many families use them (story S19). `GET /api/authors/{pseudonym}` answers the profile of the library account that holds this pseudonym now, compared without regard to case, open or closed (a closed account keeps its pseudonym and its items):

```json
{
  "pseudonym": "Owl",
  "editorial": false,
  "families": 2,
  "items": [<catalogue entries>]
}
```

- `items` are the catalogue entries (see Browsing and searching) of the items the account shared that the catalogue shows, newest first; each keeps the pseudonym its latest version was published under. By default, privacy first, only the items whose latest version carries the pseudonym of now are listed, so that a new pseudonym leaves the old one behind; the author may choose to list those of their earlier pseudonyms too (`show_earlier_pseudonyms`, `accounts-api.md`).
- `families` counts the distinct library identifiers that imported at least one of these items: a family using two of them counts once.
- `editorial` is true for the editorial account (ADR-0002).
- A pseudonym no account holds, or an account the catalogue shows no item of, answers `404` with `{"error": "unknown_author"}`. A pseudonym given up for another leads nowhere: the item page's `profile` names the one of now.

The author alone sees the suggestions received (`interface-v1.md`, Suggestions). `GET /api/account/profile`, with the session (`accounts-api.md`), answers the session's account's profile as above, with every item of theirs the catalogue shows, whatever pseudonym it carries and whatever they chose for the public profile, and no item when the catalogue shows none, and with `Cache-Control: private, no-store`; each entry also has `"suggestions": {"families": 2, "answers": 3}`: `families` counts the distinct library identifiers that ever suggested answers for the item, `answers` the suggested answers still waiting against its latest version (`GET /api/account/suggestions` lists them). Refusals: `401` `signed_out`, `404` `no_account`, `503` `unavailable`.

## Comments

A library account comments on an item page under its pseudonym (stories S28, S29). Every comment is reviewed (ADR-0005) before it shows. A comment is addressed to the item, never to an account: there are no private messages, no replies to an account, no mentions, and no route through which one account reaches another.

```
POST /api/items/{item}/comments
Authorization: Bearer <session>
Content-Type: application/json

{"text": "Learnt in a week."}
```

- The session's library account needs a verified card (`accounts-api.md`), as for sharing; a recent strong sign-in is not needed. The body is exactly `{"text"}`: any other field (a recipient, a reply, an account) answers `400` `bad_request`, and `library_identifier` answers `400` `library_identifier_not_allowed`: a comment is never joined to a family server.
- `text` is trimmed and holds 1 to 1000 characters, line breaks allowed but no other control characters.
- The review reads the comment as `{"comment": "<text>"}` in the item's language, with the item's latest version and title. Its outcome is the answer, with `Cache-Control: private, no-store`:

  ```json
  {"comment": "<32 hex>", "item": "<32 hex>", "text": "Learnt in a week.", "outcome": "published",
   "reasons": [], "commented_at": "2026-11-27T10:00:00Z"}
  ```

  `201` when `published`: it shows on the item page at once, under the account's pseudonym of that moment (a later pseudonym change does not rename it); `202` when `held` for a moderator (`moderation-api.md`, Queue), who publishes it under the pseudonym of the decision's moment, or refuses it; `200` when `refused`, with the reasons (`{"question": null, "reason", "explanation"}`).
- A library account writes at most 20 comments a day (UTC), whatever the outcome; a review that fails does not count. Beyond, `429` `{"error": "comment_quota_reached", "comments_per_day": 20, "next_comment_at": "<next day>"}`.
- Refusals: `401` `signed_out`, `404` `no_account`, `403` `card_required`, `404` `unknown_item` (the catalogue does not show it), `400` `bad_comment`, `503` `unavailable` (comments are not turned on, or the review fails).

`GET /api/account/comments` answers the session's account's comments, newest first, with the day's quota: `{"quota": {"comments_per_day": 20, "commented_today": 1, "next_comment_at": null}, "comments": [<as above>]}`. `outcome` is `published`, `held`, `refused` or `removed` (a moderator upheld a report of it).

### Reports of comments

Anyone reports a published comment from the website, anonymously, with the reasons of the withdrawal list:

```
POST /api/comments/{comment}/reports
Content-Type: application/json

{"reason": "unsuitable_content", "details": "..."}
```

- The answer is `202 Accepted` with `{"report": "<32 hex>"}` and `Cache-Control: no-store`. The report keeps no library identifier and no contact.
- For `personal_data`, `sexual_content` or `illegal_content`, the comment is hidden at once until a moderator decides. Every report waits in the moderation queue (`moderation-api.md`): upheld, the comment is removed; rejected, it shows again once no other report for these reasons waits.
- Refusals: `400` `bad_reason`, `400` `bad_request` (not exactly the expected object, details over 2000 characters), `404` `unknown_comment` (no published comment has this identifier), `503` `unavailable`.

## HTTP

- Answers are `application/json` with `Cache-Control: public, max-age=60`, except item files (`interface-v1.md`, Item files) and refusals, which carry `Cache-Control: private, no-store`.
- A database failure answers `503` with `{"error": "unavailable"}`.
